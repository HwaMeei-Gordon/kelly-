# 家教教學簡報產線（課本 → NotebookLM）

把一疊課本照片變成「每次上課一份、直接上傳 NotebookLM 就能跑出 20 頁簡報」的來源檔。

## 使用者只會給一句話

例如：**「小五上第三單元 分兩次」**、**「這單元分三次上」**、**（貼一個 Drive 連結）**。

從這句話解析出兩件事，其餘一律自己判斷、**不要反問**：

| 要素 | 怎麼取得 |
|---|---|
| **課本在哪** | 給連結就用連結；只給單元名就 `search_files` 找同名資料夾（`title contains '小五上第三單元'`），再往下找放照片的子資料夾 |
| **分幾次課** | 從話裡抓「分N次」。**沒說就預設 2 次**，並在交付時說明是預設值、可以改 |
| 科目／年級／版本 | 讀課本畫面自己判讀（頁尾通常印著版本），不要問 |
| 課本頁碼範圍 | 讀出來的頁碼就是，不要問 |

只有一種情況才停下來問：**課本資料夾是空的或找不到**。

## 產出長這樣

```
📁 <單元資料夾>/
├── 📁 課本/                    ← 使用者放的原始照片（不要動）
├── 00_課本原文還原            ← 逐頁逐字還原，備查
├── 01_教學重點整理            ← 備課用
├── 02_PPT分頁規劃             ← 課次切分與逐頁安排
└── 📁 03_NotebookLM提示詞/
    ├── 提示詞（共用）          ← 只有一份，N 次課都用這段
    ├── 第1次上課_來源          ← 整份直接上傳，不用剪貼
    └── 第2次上課_來源
```

**兩種檔案，不是兩個區塊：**

- **來源檔**（每次課一份）：**純逐頁內容**。不放使用說明、不放區塊分隔、不放提示詞。混進去的說明文字會被 NotebookLM 當成投影片內容畫上版面。
- **提示詞檔**（只有一份）：角色、視覺規範、鐵律都與課次無關，不要每次課各複製一份。

全部存成 **Google 文件**（`contentMimeType: 'text/markdown'`，不要關掉轉檔）—— NotebookLM 可以直接從 Drive 挑，使用者連下載都不用。

## 硬性事實（先記住，會影響所有決策）

| 事實 | 影響 |
|---|---|
| NotebookLM 簡報**單次上限 20 頁**（Free 8–15／Plus 20／Ultra 25），是產品硬限制 | 1 次上課 = 1 次生成 = 1 份來源檔 |
| 每次生成**沒有記憶**、彼此獨立 | 每份來源檔自帶全部內容，不可寫「同上」「延續前一份」 |
| 投影片是 Nano Banana Pro **算圖產生的圖片** | **無法插入課本原圖**。要求「直接用課本圖片」做不到 → 改成「繪製描述＋課本圖號」 |
| 產出是**連續圖片／PDF，沒有備註欄** | **絕對不可以有「講者備註」**，也不可用「備註」「補充說明」「教學提示」等別名偷渡 |
| 繁體中文是「畫」出來的，字多就糊掉、缺筆畫、寫錯字 | 版面文字設硬性字數上限。少字＝少錯 |
| 來源檔越雜，抓錯率越高 | 一個筆記本只放一份來源檔，不要同時放課本照片 |

# 流程

```
S0 取得課本 → S1 原文還原 → S2 重點提煉 → S3 切課次排逐頁 → S4 產出（Workflow 平行） → 存回 Drive
```

S0–S3 一路做完，中間不要停下來問「可以繼續嗎」。只有 S3 發現內容量塞不進 N×20 頁時才中斷回報。

---

## S0 取得課本（最容易卡的一關）

Drive 工具是 deferred 的，用 ToolSearch 載入 `search_files` / `create_file` / `read_file_content` / `download_file_content` / `trash_file` / `get_file_metadata`。

先列出照片檔，**依檔名排序**（IMG_0001、IMG_0002… 通常就是連續頁序）。

### 如果是 HEIC（iPhone 拍的，很常見）

`read_file_content` **不支援 HEIC**，一定要自己轉檔：

1. **裝套件**：`pip install --quiet pillow pillow-heif numpy`
2. **逐檔 `download_file_content`**。每次呼叫都會噴「result exceeds maximum allowed tokens」的錯誤 —— **這是正常的**，內容已存成 JSON 檔（`{content, id, mimeType, title}`，content 是 base64），路徑就寫在錯誤訊息裡。
3. **一次最多 2–3 個平行呼叫**。同毫秒完成的呼叫會撞到同一個輸出檔名而互相覆蓋，批次太大會靜默掉檔。
4. **批次轉檔**：掃 tool-results 目錄，解 base64 → `Image.open` → `convert("RGB")` → `thumbnail((1600,1600))` → 存 JPEG（品質 88，約 300–500 KB）。用 JSON 裡的 `title` 當檔名。
5. **對帳**：轉完數一次，缺哪張就補下載。不要假設全部都成功。
6. 用 **Read** 讀 JPEG（有視覺），一次 3–4 張。

其他格式（JPG／PNG／PDF）可以直接 `read_file_content`，不必轉檔。

### 先確認頁序

讀第一張，看頁尾頁碼與版本。確認照片是連續頁再往下做，不要憑檔名假設。

---

## S1 課本原文還原 → `00_課本原文還原`

逐頁把課本完整還原成文字。格式照 `references/stage-formats.md`。

- 開頭第一行固定：`> 這是由AI深度看完每一頁課本所提煉的完整課本內容`
- **只寫當前頁**。照片常拍到隔壁頁一角，要辨識出來並排除
- **不漏、不加**。課本沒有的知識、例子、補充，一個字都不准加
- 標題／內文／圖片／圖說／表格／小試身手 全部要有
- 圖號固定 `圖<頁碼>-<序號>`（例 `圖43-1`），**S3、S4 全靠它對圖**
- **小試身手逐字照抄**，含題號、選項、全形括號「（　）」、①②③④、句末句號

### 字看不清楚怎麼辦

自修／課本常有**背面印刷透光疊字**。處理順序：

1. 原圖放大重讀
2. 還不行就裁切該區域 + 拉色階（`np.percentile` 取 1% 與 55% 做 level stretch，把較淡的透印壓掉），放大 2 倍再讀
3. **還是不行就標 `［不清：？］`，絕對不要猜**，並在文件末的「還原品質備註」寫清楚是哪一題、請使用者補

猜一題錯的小試身手，比留一個空白嚴重得多。

---

## S2 教學重點提煉 → `01_教學重點整理`

- 依**課本原順序**分主題，不重排、不合併跳躍
- 100% 來自課本，零補充、零延伸
- 每個主題標對應頁碼與對應的小試身手題號

---

## S3 課次切分＋逐頁規劃 → `02_PPT分頁規劃`

把主題切成 N 次課，每次排成剛好 20 頁。

- **優先切在課本自己的「活動／單元」邊界**，讓每次課剛好用該段的小試身手收尾
- 切點不可把一個概念切成兩半跨課
- 建議結構：封面 1／本次目標 1／內容 13–15／小試身手 2–4／小結 1
- **小試身手獨立佔頁**，原文照抄、不給答案；題多可拆連續兩頁，一樣計入 20
- 每頁都要指定：課本頁數、標題、版面文字、插圖（含課本圖號）
- 頁數不多不少剛好 20，排完自己數一遍

### 實驗一律排除

除非是「晚上在房間內、用簡易生活用品就能完成的超安全小實驗」。
但實驗的**【結果】與【結論】常是核心知識**，要保留成「課本觀察到的現象」，只是不引導學生動手。在文件裡寫清楚排除了什麼、為什麼。

### 塞不下怎麼辦

內容量明顯超過 N×20 頁時，不要硬壓縮也不要偷刪小試身手。停下來說「建議改成 N+1 次」並附兩種切法比較，讓使用者決定。

---

## S4 產出來源檔（一律 Workflow 平行）

使用者已明確要求：**這一步每次都用 Workflow 平行執行，不需要再問**。

N 次課彼此獨立，用 `pipeline()` 而非 `parallel()` —— 每次課寫完就立刻接自己的驗收 agent，不必等其他次課。

```js
pipeline(SESSIONS,
  s     => agent(`寫出第 ${s.n} 次的來源檔`,        {phase:'Generate', schema:...}),
  (g,s) => agent(`驗收第 ${s.n} 次，發現問題直接改`, {phase:'Verify',   schema:...}))
```

- **generate agent** 讀 `00_課本原文還原`（唯一內容真實來源）＋ `02_PPT分頁規劃`（自己那次課的 20 頁安排），寫出 `第N次上課_來源.md`
- **verify agent** 對照 00 逐項比對，**發現問題直接用 Edit 修好再複驗**，不是只回報
- 規模：N 次課 → 2N 個 agent
- **`提示詞（共用）.md` 與課次無關，主線自己寫一次即可，不要進 workflow**

### workflow 跑完一定要做的事

各 agent 各寫各的檔，骨架容易長歪。跑完用**腳本**（不是再開 agent）掃一遍三份檔，統一補齊缺漏的骨架元素、確認頁數與欄位。機械性的正規化交給腳本，才不會有 agent 順手改動已驗收過的內容。

### 來源檔格式

格式照 `references/notebooklm-prompt-template.md`。**每頁只有四個欄位，不多不少：**

```
### 第 N 頁
- **課本頁數**：P.XX
- **內容排版**：
  - 【標題】≤14 字
  - 【主文】一句 ≤30 字（沒有就省略這行）
  - 【條列】最多 4 條，每條 ≤20 字
- **插圖引用**：畫面描述（引用課本 P.XX 圖XX-X）
```

- 順序固定：頁數 → 課本頁數 → 內容排版 → 插圖引用
- 沒有插圖的頁，〈插圖引用〉寫「無」
- **小試身手那兩頁豁免字數上限**，逐字照抄優先。在檔頭寫明豁免
- 課本沒有的圖**不准無中生有**，寧可那頁只有文字

## 存回 Drive

存在課本資料夾的**上一層**（單元資料夾），照前面的結構圖。

- `create_file` 的 `textContent` 必須把內容整段重打一次，很吃 context。**先把三份來源檔用 SendUserFile 交付給使用者**，再慢慢上傳 Drive，這樣中途出事也不會沒東西可用
- Drive **沒有更新內容的工具**。要換版本只能重建，順序一定是：
  **先 `create_file` 新的 → 確認大小正確 → 才 `trash_file` 舊的**。
  反過來先刪再建，一旦建立失敗（例如撞到 `Resource has been exhausted` 配額錯誤）資料夾就會缺檔。同名新舊並存幾秒鐘沒關係，缺檔才是問題
- 寫入可能因配額被擋。**大量連續寫入要放慢**，失敗就重試，不要放著不管
- `create_file` 回傳的 `fileSize` 常是 `1`，那是還沒轉檔完。用 `get_file_metadata` 或 `search_files`（`excludeContentSnippets: true`）**回頭確認真實大小**，確定內容有寫進去
- 建檔前確認父資料夾 `canAddChildren: true`

---

## 交付給使用者

不要只丟檔案就結束。要講清楚三件事：

1. **每次課三個動作**：加 `第N次上課_來源` 當來源 → 貼 `提示詞（共用）` → 生成
2. **NotebookLM 設定**：新筆記本（每次課各開一個）、格式選 **Presenter Slides**、語言選**繁體中文**、只放這一份來源
3. **生成後**：逐頁檢查中文字，糊掉或錯字就在該頁下方輸入修訂指令，全部輸入完再一次「生成修訂版簡報」；最後匯出 PPTX／PDF，需要的話照插圖引用的頁碼手動換上課本原圖

有 `［不清：？］` 待補的題目，要明確講是哪一頁哪一題、請使用者抄給你。

## 自我校對（交付前一定要跑，能用腳本就用腳本）

- [ ] 每份來源檔頁數剛好 20，頁碼 1–20 連續無跳號
- [ ] **來源檔是純內容** —— 沒有使用說明、沒有區塊分隔、沒有把提示詞混進去
- [ ] **全檔沒有「講者備註」**，也沒有「備註」「補充說明」「教學提示」等別名欄位
- [ ] 每頁四欄位齊全且順序正確，每頁都標了課本頁數
- [ ] 小試身手與 S1 原文逐字一致，沒有給答案、沒有憑空補題
- [ ] 沒有任何課本以外的知識、數據、例子
- [ ] 每個圖號都真的存在於 S1，沒有捏造的圖；圖號頁碼與所標 P.XX 相符
- [ ] 版面文字符合上限（標題 ≤14／條列 ≤4 條每條 ≤20／主文 ≤30；小試身手頁豁免）
- [ ] 提示詞只有一份共用檔，≤400 字，含角色／任務／視覺規範／內容鐵律／輸出品質五塊
- [ ] 每份來源檔能單獨使用，沒有「同上」「見前一份」
- [ ] 實驗符合篩選規則
- [ ] 繁體中文台灣用語，沒有簡體或中國用詞
- [ ] Drive 上的檔案大小 > 1，確認內容真的寫進去了
